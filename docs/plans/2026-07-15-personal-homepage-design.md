# 个人主页设计说明

## 背景与目标

为 GitHub Pages 静态站点提供一个可直接部署的单页个人主页。页面应以仓库中的 `wallpaper.jpg` 作为首屏背景，并包含个人介绍、可展示图片的项目列表和友情链接区域。

## 现状与约束

- 当前站点只有 `index.html` 与 `wallpaper.jpg`。
- 页面不引入构建工具、外部依赖或网络字体，保持 GitHub Pages 的直接部署方式。
- 项目与友链使用易替换的 HTML 占位内容；项目图片使用远程占位图时应可正常降级显示。

## 方案对比

### 方案一：单页滚动主页

- 优点：首屏突出壁纸与身份信息；内容区层次清晰；后续扩展成本低。
- 缺点：个人信息与项目较多时页面会变长。

### 方案二：全页玻璃卡片

- 优点：视觉氛围强，能更突出背景。
- 缺点：内容阅读性受背景影响，项目展示密度较低。

### 方案三：白色内容页加顶部横幅

- 优点：阅读性最好。
- 缺点：壁纸的存在感较弱。

## 推荐方案

采用方案一。以首屏壁纸建立个人识别，项目和链接进入高对比度内容区，兼顾视觉效果、可读性与维护便利性。

## 详细设计

### 架构

单个 `index.html` 内包含语义化 HTML、内嵌 CSS 与极少量原生 JavaScript。无外部依赖和数据请求。

### 关键组件

- 首屏：背景图、遮罩、站点名、简介、跳转到项目区的按钮。
- 项目区：响应式网格；每张项目卡包含图片、标题、简介、技术标签和访问链接。
- 友链区：紧凑的链接列表，展示名称、说明与外链箭头。
- 页脚：版权年份与 GitHub 主页链接占位。

### 数据流 / 接口

无运行时数据流。维护者直接修改 `index.html` 中的占位文本、`href` 和图片 `src` 即可更新内容。

### 异常与边界处理

- 为项目图片提供有意义的 `alt` 文本；图片加载失败时仍保留卡片文字和链接。
- 为小屏设置单列布局，避免内容溢出。
- 遵循 `prefers-reduced-motion`，降低滚动与悬停动画。

### 测试策略

- 用 HTML 文本断言检查关键区块、壁纸引用和链接属性。
- 手动使用浏览器在桌面及移动宽度下检查布局、锚点跳转与图片降级。

## 风险与待确认项

- 项目封面暂使用示例远程图片；正式发布前应替换为仓库内图片或稳定的图床链接。
- 姓名、简介、项目与友链均使用占位内容，需由站点拥有者按需替换。
